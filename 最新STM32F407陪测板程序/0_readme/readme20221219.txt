              

			
   【程序使用单片机说明】
   
   
	★ 主控stm32f407vet6 rom：512k   sram：128+64 = 192k
	
	
   【flash 存储分配】
   
   
    ★ 0x0000 0000  --------   0X0000 0008    保存设置的RSSI         （RSSI阈值）       长度 9字节
    
    ★ 0x0000 0009  --------   0X0000 0027    保存设置的FEATURE      （特征值）         长度 31字节
   
    ★ 0x0000 0028  --------   0X0000 0045    保存设置的Pro name     （项目名称）       长度 30字节
   
    ★ 0x0000 0046  --------   0X0000 0048    保存设置的唯一码长度或者特征              （当唯一码 < 0x83 时，表示唯一码的长度，否则表示特征）   长度 3字节
	
	★ 0x0000 0049  --------   0X0000 0051    保存设置的老的上位机需要的唯一码长度或者特征              （当唯一码 < 0x83 时，表示唯一码的长度，否则表示特征）   长度 3字节

	★ 0x0000 0052  --------   0X0000 005B    保存设置的工单号前6位存数字                长度 10 字节
	

	【NRF52832 BLE模块特性】
	
	
	★ NRF52832模块不带flash，相关的参数每次上电时均不能保存
	
	★ 为了完成保存相关的测试参数的功能，由stm32f407保存相关参数，并在没次上电时自动给NRF52832设置
	
	★ NRF52832模块为了追求效率，以及为了安全考虑，在开始扫描工作后，不在接受通过串口来设置相关的参数，所以开始扫描后如果
	   要想在进行相关的测试，需要从启NRF52832在进行测试
	   
	★ 上电初始化完成后，lcd界面上有 显示 cmd set mode，表示可以设置相关的参数 （rssi + feature + 字节序 + mac掩码）
	
	★ stm32上电完成初始化后，出现 cmd set mode， 在此模式下，可以有两种设置方式，一个是从flash中读取数据并设置，
	   置需要按断key3， 就会执行上次保存在flash中的相关参数，并开始扫描
	
	★  如果要接收空中的任意数据包，并查看接收的原始数据，需要复位后，设置rssi， mask_raw_data，然后发送 use_default_settings
	    此时串口2（ble模块），接收到的数据通过串口1发送出来，通过此方式可以查看一款产品的ble广播原始值，并确实特征值
		
	★  
	
	
	
	
  【程序整体逻辑】
  
		★  开机开始设置参数，设置完参数后开始工作
  
  
		
		★  程序通过STM32 的usart1 和 pc通信	，设置项目名称，rssi阈值，过滤特征值，开始扫描，默认参数开始扫描，mac的大小端设置
		
		
		
		★  pc 和 stm32的串口1的通信设置为，  波特率= 115200   8N1
		
		
		    [ rssi_set_cmd    ] = 7F 07 81 00 00 C4 42                     //  设置rssi值  c4 就是rssi = -60
			[ freture_cmd     ] = 7F 0C 82 00 00 02 01 05 1B FF CA A6      // 设置过滤广播特征值，特征值 =02 01 05 1B FF CA
			★  上面的命令需要以16进制发送，发送协议参考 ：https://itead.yuque.com/ge3uqx/bpp8un/gtfawb2ma00h3kkg?singleDoc# 《陪测板通信协议》
			
			[ start_scanning  ] = start_scanning
			[ byte_order_set  ] = byte_order_set
			[ mask_raw_set    ] = mask_raw_data
			[ prj_name_set    ] = prj_set=S60TPF
			[ use_default_set ] = use_default_settings
			[ only_len_set    ] = only_len_set=0x06 
			[ work_num_set=   ] = work_num_set=253043
            [ no_work_num\\r\\n ] = no_work_num
			
			★  上面的命令需要以字符串发送，且命令以\r\n 结束
			
			★   为了适配 pc上位机， pc上位机目前对cmd的处理会有两套逻辑
			 A :  当cmd >= 0x83 时， 使用老逻辑，就是上位机会通过提前准备好的映射文件，来根据文件来确实 唯一码的长度，从而解析数据
			 B:   当cmd  < 0x83 时， 使用新的逻辑来解析cmd 数据， cmd=多少，就表示唯一码的长度是多少
			 // 0x7f len  cmd  0x00  0x00         唯一码                        sn   rssi  fcs
             //   1   1    1    1      1    only_global_pc_set_value            7     1     1 
			 C ： cmd就是上面命令中的cmd
			 D : 要想使用老的cmd解析规则，需要在开机后设置，先设置老的cmd， 然后在设置实际的cmd（mac占用几个字节），按 key3按键开始扫描执行
			 E ：如果想使用曾经设置好的，保存在flash 中的老的cmd解析， 需要先按key2， 确认启动老的cnd解析，然后在按key3
			 f : 开机后确认lcd上的参数无误后，直接使用，按key3， 此时使用新的cmd解析规则
			 
			
		
		★  NRF52832 BLE 模块开始工作后，一直扫描符合rssi +特征值的广播，并叫符合要求的数据解析后，通过串口发送给stm32的 usart2
		
		★  stm32的usart2 中断中，不停地解析接收数据
		
		★  stm32将符合rssi + 特征值的 + mac唯一 + sn=14个字符的值，通过lcd显示，并通过usart1发送给pc
		
		★  解析数据的过程是，nrf52832 接收并解析号数据，通过nrf52832的串口，发送给stm32的串口2
		
		★  stm32 串口2接受数据，并保存在环形换从区
		
		★  stm 32的 void usart2_receive_print_task(void * pvParameters) 的任务一直接收数据，并解析收到的数据长度达到211时（），开始截取数据
		
		★  nrf 52832发送解析号的数据格式为 ：[RSSI=-22] ---> [CH=37] ---> [tx_pwr=127] ---> [DECRYPT_MAC]=DC5475A87ACC ---> [DECRYPT_SN]=23025100000298
		
		★  stm32 任务usart2_receive_print_task 先判断截取的mac数据是否全部一直，且截取的mac数量要大于等于2
		
		★  如果mac全部一直的情况下，截取sn数据，sn数据是否完全一样
		
		★  继续判断sn的数据长度 =  14个字符长度
		
		★  都满足的情况下，在lcd 上显示黄色的 mac + sn  +ch +rssi
		
		★  关闭usart2，放置继续收到有效数据
		
		★ 打开定时器开始定时 （5s timeout）
		
		★  发送组合好的mac +sn 给上位机
		
		★  等待上位机回复
		
		★  超时时间内收到pc 的回复，显示绿色 mac  sn  ，ch， rssi
		
		★  超时时间内没有收到pc的有效回复， 显示红色的   mac  sn  ，ch， rssi
		
		★  下位机对于PC的回复内容支持如下两种
		    1 :  pc 在解析到正确的数据后，发送“test_ok\r\n”
            2 :  pc 在接线到正确的数据后，发送0x7f 07 cmd 80 00 00 fcs			
		
		★  关闭定时器
		
		★  打开usart2
		
		★  继续下一轮接收数据

		【程序和 pc通信接口】
		
		★  使用stm32f407 主板的 usart1来通信 （115200  8N1），没有使用虚拟串口的原因是，虚拟串口没有硬件串口稳定，且虚拟串口的驱动挑系统
		    工厂端的电脑系统不见得能安装
			
		★  使用此套系统，需要给陪测板单独供电5V1A （以前使用虚拟串口即供电，又通信，有时候pc接口供电能力不足，导致系统运行不稳定）
		
		★  上位机如果需要使用自动串口检查（因为使用了硬件串口，如果接入多个硬件串口时，pc无法区分），可以使用CH340B 串口信息，设置特定串口信息
		    具体设置方式见链接https://itead.yuque.com/ge3uqx/bpp8un/gtfawb2ma00h3kkg?singleDoc# 《陪测板通信协议》
			
		★  当下位机获取到数据并发送给pc后，pc在2s时间内没有返回的话，下位机会继续发送命令，2s间隔，直到超时

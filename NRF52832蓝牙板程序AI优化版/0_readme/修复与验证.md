# 修复记录与验证说明

本次针对应用层和实际运行路径进行可靠性审查与重构，以修改前备份 `baseline_20260911` 为比较基准，最终软件验证日期为 2026-09-15。保留采集用途、七条正常命令、成功回复、版本行格式、扫描参数和两种数据协议。以下列出已确认的问题，不把所有 SDK 或硬件风险声称为已经排除。

## 已修复的问题

| 原问题与触发条件 | 影响 | 处理方式 |
|---|---|---|
| 特征字符串超过 64 个十六进制字符仍持续写入 32 字节数组 | 越界破坏内存 | 先检查容量、偶数字符和每个字符，再一次提交 |
| 特征转换部分失败仍可能沿用成功标志 | 错误条件被接受、旧配置被破坏 | 转换使用临时数组；失败返回 false 并保留上次有效配置 |
| 可设置 32 字节特征，但广播最大长度为 31 字节 | 设置成功却永远无法匹配 | 将有效特征上限限制为 31 字节，拒绝不可用配置 |
| `strtol` 未检查空串、未读入数字和溢出；RSSI 范围失败却可能改变成功标志 | 非法配置被接受或默认阈值选择错误 | 完整校验后才设置 RSSI 值与有效标志 |
| `str_extract` 未接收目标容量 | 提取内容可能越界 | 接口增加容量，失败清空目标，所有拷贝有边界 |
| `decrypt_data` 先 `memset` 再验证指针／容量 | 空指针或负容量可能写坏内存 | 先验证输入及输出容量，失败不写目标 |
| 原 XOR 索引已有上限保护，但其他入口边界不足 | 异常包处理不完整 | 保留索引规则，增加固定长度和指针校验，测试全部 256 个索引 |
| BLE 报告直接按来源长度 `memcpy`，主循环之后才检查超过 31 字节 | 检查太晚，可能破坏报告队列 | 回调入队前拒绝超长及非法指针 |
| 默认模式遇到一次特征匹配就把默认标志清零 | 运行中意外变成自定义模式，后续报告消失 | 过滤成为无副作用的判断，配置与每包结果分离 |
| UART 混用 nrfx API 和手工 STOP／ENDRX 操作，关掉 RXTO 中断 | 驱动与硬件状态不一致，超时／满缓冲后可能停收 | 保留驱动中断，使用异步 STOP→回调→硬件停止确认→主循环取走的统一流程 |
| RX 回调提前置 ready、复制公共数组后又启动同一缓冲 | 主循环可能读到被覆盖或尚未稳定的数据 | 停止确认后由主循环复制，复制完成才重启 DMA |
| 错误接收仅清定时器、零字节和部分超时分支无可靠重启 | 出错后不再接收命令 | 正常、满缓冲和错误结果统一交付与恢复 |
| 初始化前调用未初始化驱动的 `uninit` | 打开 SDK 断言时可能停在错误处理 | 按状态正确初始化；UART 重复初始化直接返回 |
| TX 启动后才置自定义 busy 标志 | 极短发送的完成回调可能先到，busy 被重新锁住 | 直接查询 nrfx 发送状态，不维护重复 busy 状态 |
| `print` 忽略发送返回值，超时后复用仍被 DMA 使用的全局缓冲 | 输出丢失或被后续内容覆盖 | 发送前验证状态和长度，复制到驱动自有 RAM；发送失败不覆盖在途数据 |
| 用 `strstr` 在任意位置搜索命令，单次只处理一个分支 | 错误前后缀也可能生效；多条命令或分片丢失 | 按 CRLF 分行、精确匹配，每条独立校验；开始后锁定配置 |
| 某些广播无法解码又没显示原始 DATA 时没有换行 | 多条串口记录粘在一起 | 保持有效输出格式，异常情况下也结束当前行 |
| 未入工程的旧 `fputc` 使用 UART0 TXDRDY，而实际启用 UARTE0 | 将来误加入工程会忙等 | 移除不兼容实现，保留说明；应用统一用 `print()` |

## 结构与注释整理

- 将配置集中为 `app_config_t`，替代分散的 `run_flag_a`／`run_flag_b` 等相互依赖标志。
- 将命令解析从 DMA 驱动拆到 `uart_commands.c`，将纯广播过滤／字段解析拆到 `adv_parser.c`。
- 广播队列索引改为模块私有，主循环通过函数取数据或丢弃报告。
- 将 `data_ processing.c` 重命名为 `data_processing.c`，同步更新两个 Keil 目标及 `.uvoptx` 中的路径。
- 清除核心模块中的大段废弃代码和空模板注释；补充中文说明、缓冲所有权、协议偏移、硬件资源占用和配置阶段含义。
- 简化 LED、蜂鸣器和保留示例的代码，保留其原行为；不将阻塞式按键示例引入扫描主循环。

本次没有整体迁移 SDK 文件，也没有改变 SoftDevice 二进制、Keil 内存区域、波特率、引脚、扫描窗口或 XOR 码表。版本字符串仍为 `V 1_0_7`，用于保持 STM32 上位机解析兼容；本次修订可用本文件和备份区分。

## 保留的限制

115200 串口的输出带宽有限，持续输入高于输出速度时，127 条广播队列仍会填满并丢弃新报告，这是保留的有界策略。没有添加去重、改变扫描占空比或启用硬件流控，以免改变采集用途及上位机协议。

串口在 STOPRX 后等待主循环取走再重启，有接收间隙；因此建议按“发送命令→等待应答”交互。打印采用有限等待，持续硬件故障时可能丢弃输出，但不会复用正在发送的数据，也不会无限阻塞主循环。

自定义模式缺少 RSSI／特征设置时仍允许执行开始命令，但不会产生符合条件的输出；这是保留的原业务行为。明文模式仍只按长度和固定偏移解释数据，默认模式下其他来源的 31 字节广播也可能被解释；需要区分设备时应使用自定义特征筛选。

# 代码审查、结构优化与验证报告

## 交付结论

已对当前 `ble_passive_scanning` 目标实际使用的代码完成审查、修复和结构整理，并补充[运行说明](运行逻辑与流程图.md)与[独立流程图 PNG](程序流程图.png)。保留“配置 NRF52832 → 接收并核验蓝牙产品信息 → 上传上位机 → 等待确认/超时 → 继续扫描”的业务目的。

## 主要发现及修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 1024 字节环形数组按 2048 字节清零 | 开机及 USART2 恢复时覆盖相邻内存 | 按数组真实 `sizeof` 清零，加入相邻哨兵测试 |
| 中断与任务分别修改缓冲长度 | 长度丢更新、读写错位 | 保存/恢复 PRIMASK 的短保护区、实际读取计数与溢出统计 |
| `vsprintf` 无边界，多个发送者共用 DMA 缓存 | 内存越界、发送过程中数据被改写 | 有界格式化、每端口互斥、DMA 停止后再修改缓存 |
| DMA 零长度、旧完成标志和硬件故障未处理 | 死等或误判发送完成 | 空发送直接返回、清理状态、错误检测和有界无进展等待 |
| PC 按一次接收长度判断完整命令 | 分包/粘包丢指令 | 连续字节组帧，分别校验二进制与 CRLF 文本 |
| 特征字符串、32 字符 CHIP ID、计时文本和 LCD ID 缓冲不足 | 结束符或格式化内容越界 | 正确容量/有界输出；LCD ID 直接比较数值 |
| 任意 `only_len_set` 值可成为数组长度，旧 CMD 污染长度 | 组包越界、错误产品数据 | ID 长度限定 1～16 字节，旧 CMD 单独保存；字段失败不上传 |
| NRF 数据被截断仍解析、MAC/SN 分开查找 | 不完整数据或产品配对错误 | 按完整行保留 MAC/SN 配对，至少两条一致且本批无冲突 |
| 多个共享配置标志和跨轮成功标志 | 等待应答时参数被覆盖、重试继承旧成功 | 请求队列保存快照，USART2 串行处理，每轮独立状态 |
| PC 确认模板只在读取 Flash 时更新 | 现场配置后确认无法匹配 | 每次上传固定本轮 CMD，只在等待状态接收确认 |
| `(计数 % 4) == 0` 在同一时间段反复为真 | 首发后连续多次重复上传 | 首发快照、约 2 秒与 4 秒各重发一次，5 秒超时 |
| 中断绘屏、发串口及长时间忙等；临界区内延时 500 ms | 串口/任务响应受阻，LCD 重入 | ISR 仅采集/计时；同一业务任务拥有 LCD/Flash；等待让出 CPU |
| Flash/SPI 永久等待、读失败后仍可能擦写 | 开机卡住、配置损坏 | 有界等待、地址/页/扇区校验、WEL/SPI 状态检查，失败终止后续步骤 |
| SPI 调速写入未初始化结构体 | SPI 模式等配置被意外覆盖 | 只修改分频位，保留其他寄存器位 |
| 栈溢出/断言仅打印后继续，启动失败可落出 main | 损坏状态继续执行业务 | 统一异常停机，调试器可查看错误原因、文件和行号 |
| HSE 启动失败仍可能进入按 168 MHz 假设的应用 | 串口和时间配置错误 | main 重新计算实际系统时钟，不符合 168 MHz 时停机 |
| 蜂鸣器初始化 PE2、控制宏却写 PA15 | 初始化与实际控制引脚不一致 | 统一为既有初始化使用的 PE2；长鸣循环改 32 位防回绕 |
| GPIOH/I 输入地址宏指向 GPIOF/G | 使用对应宏时读错端口 | 改为对应 GPIOH/I 基址 |
| 链接脚本保存在构建产物目录 | 清理产物可能同时丢失工程配置 | 复制原布局到稳定的 `1_user/stm32f407_memory.sct`，两工程统一引用 |

## 结构整理

- `main.c` 只负责启动顺序、时钟核对和异常入口。
- `my_task.c` 按 PC 接收、配置处理、NRF 行解析、上报事务、重试结果分成小函数；共享状态集中声明并说明所有者。
- `app_protocol.h` 提供不依赖 STM32/RTOS 的协议函数，可在主机直接回归。
- `ui_lcd.c` 拆为固定布局、保存配置显示、命令帮助、版本读取与初始化入口。
- `dma.c` 以端口表合并共用发送流程，Flash 驱动统一片选、状态、地址、页/扇区操作。
- Keil/EIDE 按应用协议、串口 DMA、显示输入、板级存储分组；保留原 63 个 C 编译单元，检查确认无重复、无缺失、两工程一致。
- 保留现有硬件驱动接口、正常串口协议及 Flash 存储布局，源文件延续 GBK 编码，文档为 UTF-8。

## 有意修正的行为边界

正常逐条配置并等待回复的操作保持原用途。错误和并发路径有所修正：非法参数/损坏帧不再接受；配置命令按 FIFO 执行，不再用共享标志覆盖；配置失败后需重新确认；开始扫描前检查有效 ID 长度；中断耗时动作移到任务；重复重发按时间段去重。

原协议没有事务序号，不能通过本次重构解决“非常迟到且 CMD 相同的上一轮回复被新一轮接收”的歧义。要完全解决，需要同步修改上位机和 NRF 协议。本次保留线上格式及 `tesk_ok`、`cipnertext_set_ok` 等原拼写。

## 上板检查及未消除的限制

1. **Keil Rebuild 与内存图。** 使用 ARMCC 5.06 完整重建，核对栈/堆和 SRAM/CCM 占用；确认所有 `.dma_buf` 位于 DMA 可访问 SRAM。新增配置队列与串口互斥量需要实际运行时检查堆余量和任务栈高水位。
2. **硬件一致性。** 核对外部晶振、实际 168 MHz 时钟、蜂鸣器 PE2 接线、LCD 16 位 FSMC 读取及图像/文字。PE2 修复依据是源码中的初始化配置，未取得原理图做独立验证。
3. **上下位机完整流程。** 分别用新/旧 CMD、6/7/8 字节特征值、6 字节 MAC 与 16 字节 CHIP ID、KEY3 保存配置、原始广播/默认设置、明文/密文验证。真实 NRF 应答需包含原协议的 CRLF。
4. **扫描与时序。** 单设备及双设备并存、快速/迟到/不回复 ACK、连续多轮扫描，核对黄色等待、约 2 秒/4 秒重发、5 秒超时、绿色/红色和 USART2 恢复。
5. **满载与按键。** 保留普通 DMA+IDLE 接收与 1024 字节环形容量；超长无间隔流仍可能丢数据。现在有断流统计并丢弃损坏批次，不承诺无限输入不丢包。Flash 擦写时极短按键仍可能漏采，需实测操作手感。
6. **存储可靠性。** 配置仍在原单扇区布局，没有 CRC、双副本或提交标记；擦写过程中掉电可能丢配置，也没有每次写后逐字节回读。改变这些需要另行确定持久化兼容策略。
7. **故障诊断。** DMA/SPI 的无进展等待以循环预算退出，Flash 以软件等待预算退出，硬件负载下并非精确毫秒上限。异常停机保留引脚当时状态，不自动重启或执行额外硬件动作；没有在本次添加看门狗或 HSE/PLL 启动阶段恢复机制。

软件显示版本沿用 `V 1_0_4`，可结合编译时间和本次修改哈希区分构建。本报告不宣称已经证明所有硬件条件下无 bug。

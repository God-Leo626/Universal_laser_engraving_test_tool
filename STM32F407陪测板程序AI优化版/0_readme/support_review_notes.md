## 提供给主任务的接口约定

- `button_process_events()`：由串口2业务任务周期调用，先采样再执行按键动作。KEY1 切换 NRF 解析方式，KEY2 选择旧 CMD 规则，KEY3 申请使用保存配置开始扫描。
- `button_sample_events()`：只消抖和锁存动作。在等待 NRF 应答期间调用它，回主循环后再执行，避免等待一条命令应答时插入新的按键命令。
- `time3_update_display()`：由同一任务调用，消耗 TIM3 的显示请求，每秒更新一次计时文字。TIM3 中断仍每 500ms 计数，累计 10 次时产生原 5 秒上位机应答超时标志。
- `w25q32_last_operation_ok()`：在一次 Flash 调用后立即检查。正常读取与保存地址完全沿用旧布局：RSSI `0x00`、特征 `0x09`、项目名 `0x28`、新唯一码长度 `0x46`、旧长度 `0x49`。

当前所有 LCD 与 Flash 操作由启动阶段或串口2任务执行，ISR 不操作这两个外设。Flash 内部的全局扇区缓冲和操作状态要求单调用者，新增其他任务时必须另行建立互斥。

## 启动与运行路径

1. 启动函数配置中断优先级与 SysTick。
2. 初始化 LCD、NRF 电源控制、上位机串口路由、蜂鸣器和 SPI1；显示开机图案 600ms。
3. 初始化 USART1/USART2 为 115200，配置 TIM3 为 500ms 周期但不启动，初始化三个按键，并打开 NRF 电源。
4. 画固定界面，读取并显示 Flash 保存设置，向上位机输出命令示例。
5. 最多等待 2 秒，从 USART2 环形缓冲累计接收 NRF 启动信息并显示版本，然后蜂鸣器提示 10ms。
6. 调度器启动后，由主任务处理命令/扫描/结果；支持模块负责按键、计时、显示、存储和字节/字符串转换。

## 验证

在工作区执行：

```powershell
python tools/test_support.py
```

使用 MinGW GCC，以 `-std=c99 -O2 -Wall -Wextra -Werror` 编译，测试生产 `data_processing.c` 和 `w25q32.c` 的完整函数体，只替换硬件 include/硬件接口。结果保存在 `0_readme/validation/support_host/results.txt`。

已通过：

- 数据转换：精确容量、空指针、零长度、非法十六进制、输出不被部分改写、有符号边界、两个相等字段、残缺字段拒绝。
- Flash 模拟：两片芯片隔离、非对齐跨页写、跨两个已占用扇区写、前后未覆盖数据保留、擦除态直接写、地址/页/扇区拒绝、零长度不写、WEL 失败、BUSY 超时、SPI 故障退出及片选释放。

主代理统一执行 Cortex-M4 全工程 C 编译检查，结果以 `0_readme/validation/arm_gcc/compile.log` 为准。主机模拟不等同于 Keil 完整链接，也不验证真实 SPI/LCD 时序。

## 仍需实板确认的边界

- 上板验证按键短按/抖动、持续 NRF 串口输入、扫描返回和 LCD 计时并行情况；Flash 擦除/写入阻塞期间仍可能推迟极短按键采样。
- Flash 的 3000ms 普通操作及 120000ms 全片擦除为故障退出预算，真实器件最坏时间、状态寄存器和总线时序需结合实物型号验证；当前无写后逐字节回读验证。
- 现有配置位于同一扇区，擦除后回写期间掉电仍可能损坏配置；若增加双备份/CRC/提交标记，会改变持久化格式和旧版兼容策略，本次保留格式并明确此限制。
- 通用字符串接口要求输入真实 NUL 结尾；XOR 和十六进制数组转字符串的旧接口不携带源/目标容量，调用方必须保证范围有效。
